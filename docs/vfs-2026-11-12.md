# VFS: deskryptory plików — etap 1.2 (2026-11-12)

Drugi krok planu: system ma tablicę deskryptorów plików per proces. Wcześniej
każda operacja plikowa wymagała pełnej ścieżki (`BWS 2/3/5`), a bramka SysV
znała wyłącznie `fd 1 i 2`. Żadna libc POSIX nie może na tym stanąć, bo
`crt1` otwiera pliki przed `main`.

## 1. Punkt wyjścia

| Obszar | Przed |
|---|---|
| Deskryptory | brak pojęcia fd; BWS przyjmował ścieżkę przy każdym wywołaniu |
| `write` w bramce SysV | tylko fd 1/2, każdy inny → `EBADF` |
| `open`/`read`/`lseek`/`fstat` | brak |
| Inicjalizacja | bramka SysV nie miała punktu startowego w `kernel.cpp` |

## 2. Architektura

Podział jest celowo ostry, bo polityka deskryptorów musi być testowalna bez
QEMU:

```mermaid
flowchart LR
    R3["Ring 3: open/read/write/lseek/fstat"] --> G["int 0x80"]
    G --> D["posix_dyspozytor (przenosny)"]
    D --> S["posix_jadro (uslugi)"]
    S --> V["vfs_jadro: PSF + PZB + SMAP"]
    V --> C["vfs: czysta logika tablicy"]
```

| Plik | Rola |
|---|---|
| `jadro/vfs/vfs.h` | ABI: `VfsDeskryptor`, `VfsStat`, flagi, kody wyników |
| `jadro/vfs/vfs.cpp` | czysta logika: przydział, izolacja PID, limity, flagi |
| `jadro/vfs/vfs_jadro.h/.cpp` | jedyne miejsce łączące VFS z PSF, PZB i pamięcią Ring 3 |

## 3. Decyzje projektowe i ich uzasadnienie

### 3.1 Tablica dwuwymiarowa `[pid][fd]`, nie wskaźnik w `proces_t`

Zmiana `proces_t` wymagałaby korekty `static_assert` na offsety w kilku
modułach (`przerwania.S`, `idt.cpp`, `scheduler.cpp`, `loader.cpp`) — to
zmiana ABI schedulera podejmowana dla wygody, a nie dla bezpieczeństwa.
Tablica wyspecjalizowana daje ten sam efekt izolacji i nie dotyka ABI.

**Izolacja jest strukturalna**: deskryptor procesu 3 leży w innym wierszu niż
ten sam numer procesu 4. Test sprawdza to przez zapisanie całego wiersza
procesu 3 i weryfikację, że proces 4 widzi nadal tylko swoje pliki.

### 3.2 fd 0/1/2 nigdy nie trafiają do pliku

`vfs_zarezerwuj()` szuka wolnego slotu od 3 w górę. Zamknięcie `stdout`
zmienia tylko flagi na 0 (brak dostępu) i **zostawia slot zajęty**.
Gdyby numer 1 mógł zostać przydzielony plikowi, `printf()` zaczęłoby pisać
do przypadkowego pliku użytkownika — klasyczne źródło utraty danych.

### 3.3 Scieżka za długa jest odrzucana, nie obcinana

Obcięcie zmieniłoby plik, na który wskazuje deskryptor. `open()` zwraca
`ENAMETOOLONG` (mapowane na `EINVAL`, bo PSF nie rozróżnia tych przypadków —
lepiej mieć jeden, sprawdzalny kod niż dwa udające precyzję).

### 3.4 `O_TRUNC | O_RDONLY` odrzucane, choć Linux je przyjmuje

Cicha utrata danych użytkownika nie jest „zgodnością", tylko błędem.
`open("/plik", O_RDONLY | O_TRUNC)` zwraca `EINVAL`.

### 3.5 Odmowa `read()` na terminalu

Wejście interaktywne idzie przez BWS 4. Czytanie go w syscallu wymagałoby
blokowania procesu, którego scheduler nie ma. `-ENOSYS` jest uczciwe:
aplikacja dowie się, że ścieżki nie ma, zamiast dostać `0` (EOF) i uznać
wejście za zamknięte.

### 3.6 Polityka PZB odtworzona lokalnie, nie linkowana z `syscalls.cpp`

Helpery `proces_ma_prawo` i `proces_moze_modyfikowac_sciezke` mają
**wiązanie wewnętrzne** (anonimowa przestrzeń nazw) i nie są widoczne dla
linkera poza `syscalls.cpp`. Zamiast zmieniać ich widoczność w module BWS
(ryzyko kolizji nazw i rozjazdu polityki), `vfs_jadro.cpp` sprawdza
dokładnie te same bity `PRAWO_*` i ten sam próg `PZB_UZYTKOWNIK`, z tą samą
listą drzew chronionych. Reguła jest identyczna i sprawdzona testem QEMU.

### 3.7 `VfsStat` z ukladem Linux x86-64 (144 B)

Każdy nagłówek `<sys/stat.h>` w obcym libc zakłada konkretne offsety. Zła
kolejność pól nie daje błędu kompilacji — daje śmieci w aplikacji. Dlatego
offsety są sprawdzane testem hosta.

### 4.1 Weryfikacja, że test nie jest pusty

Test przeszedł za pierwszym razem, więc sprawdziłem, czy faktycznie coś
sprawdza — celowo zepsułem logikę:

| Wprowadzona usterka | Wynik testu |
|---|---|
| usunięta kontrola `d.pid != pid` | nadal PASS — **test był za słaby** |
| wspólna tablica dla wszystkich PID | **FAIL 4/112** — test łapie realny błąd |

Pierwszy wynik ujawnił, że izolacja jest strukturalna (dwuwymiarowa tablica),
więc kontrola `d.pid != pid` nigdy nie zawodzi. Zamiast usuwać martwy kod,
wzmocniłem test: zapelnia cały wiersz jednego PID i sprawdza, że drugi PID
nie zyskuje ani jednego deskryptora. Dopiero ta wersja wykrywa wspólną tablicę.

### 4.2 Pełny cykl w QEMU (kategoria 7)

`open(O_CREAT|O_TRUNC) → write → close → open(O_RDONLY) → read → lseek → fstat
→ close → podwójne close`. Sprawdzane jest, że dane przetrwały zapis (PSF),
że `read()` na końcu zwraca 0, a powtórne `close` zwraca `-EBADF`.

### 4.3 Regresja bezpieczeństwa (kategoria 8)

Ten sam proces ma `PRAWO_PLIKI_ZAPISZ`, więc odmowa zapisu do `/system`,
`/jadro` i `/programy` **musi** pochodzić z reguły drzewa, a nie z braku
prawa. To bezpośredni test, że polityka PZB nie wyciekła przez nową ścieżkę.

## 5. Zmiana w manifeście aplikacji testowej

`MANIFEST_TEST` otrzymał `pliki_zapisz`. Uzasadnienie: aplikacja „Testy
systemu" weryfikuje zapis przez VFS, a PZB-4 nadal blokuje wszystkie drzewa
chronione. Sama zmiana manifestu bez testu bezpieczeństwa byłaby osłabieniem
polityki, dlatego kategoria 8 w `test-elf-exec-qemu` sprawdza wprost, że
`/system`, `/jadro` i `/programy` są nadal niepisywalne.

## 6. Czego świadomie NIE ma

| Brak | Dlaczego |
|---|---|
| `dup`/`dup2`/`pipe` | wymagają współdzielenia wpisów tablicy; osobny punkt |
| `opendir`/`readdir` | katalog otwiera się poprawnie, ale `read()` zwraca `EISDIR`; listowanie ma osobne API PSF |
| `read` z terminala | wymaga blokowania procesu — czeka na wątki (etap 4) |
| `O_APPEND` atomowość | jednordzeniowo, więc nie ma wyścigu; przy SMP trzeba poprawić |
| `mmap` plikowy | nadal `-ENOSYS`; wymaga demand pagingu |
| Normalizacja `..`/`.` | odrzucana jawnie; PSF nie ma rozwiązywania ścieżek względnych |

## 7. Kolejny krok

Punkt 1.3 planu: rozszerzenie bramki o `set_tid_address`, `set_robust_list`,
`prlimit64`, `sched_getaffinity`, `writev`, `ioctl` (`-ENOTTY`, nigdy 0) oraz
prawdziwy `brk`. To dokładnie ta lista, której brakujące wywołania musl
rozpoznaje przez `-ENOSYS` — bez `set_tid_address` i `prlimit64` `crt1`
przerywa start jeszcze przed `main`.
