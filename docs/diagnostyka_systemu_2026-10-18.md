# Diagnostyka systemu — native Ring 3 diagnostics

The utility is a normal `.cebula` application, using BursztynUI, the existing BUR loader, window manager, theme/font services, clipboard and PSF file APIs. Hardware state comes exclusively from the kernel's read-only BWS 91 API. It neither maps hardware nor accesses PCI configuration, I/O ports, kernel objects or DMA buffers.

## Findings and architecture

Previously, serial logging and several specialized diagnostic facilities existed, but there was no general early-boot hardware/driver registry or safe system-wide Ring 3 diagnostic snapshot. PSF supports names up to 55 bytes; this implementation nevertheless uses short report/config filenames. There is no generic application-preference service, ACPI device-namespace enumeration, I2C host stack or HID-over-I2C driver to reuse.

The new store has 384 device/binding records and 1,024 log records. It is statically initialized and works before the heap, filesystem, GUI and Ring 3. IRQ-save atomic locking protects readers and writers; no logger, filesystem operation or allocation runs while holding that lock. Overflow retains existing records/early boot evidence and reports dropped-record counts. Drivers continue operating when diagnostic capacity is exhausted. Input readiness is supplied separately by the actual common input registry, so record-store overflow cannot invent an input failure.

PCI detection and driver readiness remain separate. Inventory records have BDF/IDs/class and driver bindings are children. xHCI controllers, USB devices and HID interfaces form further parent/child levels. The existing multi-controller/composite-HID enumeration is the source of USB data; diagnostics perform no additional USB enumeration. A failed HID interface does not hide other interfaces.

States are numeric enums: inactive, OK, not found, unsupported, warning, initialization failed, timeout, driver missing, detected-but-unsupported, critical. Polish labels are generated by the application/shared report formatter. Numeric failure codes map to stable identifiers, including `INPUT-USB-XHCI-0001`, `INPUT-HID-0002`, `AUDIO-HDA-0001`, `STORAGE-AHCI-0001`, `INPUT-KBD-0001` and `INPUT-PTR-0001`.

An aggregate category is working if any usable binding exists; otherwise its most severe published state wins. Keyboard/pointer health comes from registered keyboards and armed pointers across PS/2, USB and VirtIO. PS/2 absence never overrides working USB/VirtIO input. Touchpad status is independent. Without an ACPI namespace enumerator, the utility explicitly reports touchpad detection as unavailable/HID-over-I2C unsupported, with `detected=false`; it does not fabricate a detected ASUS touchpad.

Error counts include failed/timeout/critical bindings, explicit error events and missing usable keyboard/pointer sources. Warning counts include warning/missing-driver/detected-unsupported bindings, explicit warnings and incomplete stores. Ordinary absent PS/2/network devices are informational. Generic serial messages are categorized for filtering; their English wording never determines driver readiness.

Serial output remains unchanged. Exported diagnostic messages redact opaque address/large numeric tokens, including decimal and unprefixed addresses. Explicit BAR, USBSTS and PORTSC metadata is retained; other hardware scalars are available through typed fields. The public ABI contains no kernel pointers or DMA addresses and has explicit zeroed alignment bytes.

## Public BWS ABI

`BWS_DIAGNOSTYKA_SYSTEMU = 91`; the next available BWS number is 92. Existing syscall numbers are unchanged.

Call convention: `bws_wywolaj(91, (uint64_t(DIAG_ABI)<<32)|command, output, capacity, index)`.

| Command | Output | Purpose |
| --- | --- | --- |
| 1 `DIAG_GET_SUMMARY` | `DiagSummary`, 152 bytes | Overall/category states, generation, device/driver/log counts, errors/warnings, input readiness, serious-problem flag, overflow counts |
| 2 `DIAG_GET_DEVICE` | `DiagDevice`, 400 bytes | One structured device/binding |
| 3 `DIAG_GET_DRIVER` | `DiagDevice`, 400 bytes | One binding with a nonempty driver name |
| 4 `DIAG_GET_LOG` | `DiagLog`, 256 bytes | One immutable retained boot/runtime diagnostic message |

All calls return 1 on success, 0 on invalid command/version/index/buffer or copy failure. Undersized buffers are rejected without partial writes. Oversized capacities above 64 KiB and overflowing pointer ranges are rejected. The existing user-range validation and copy-to-user functions perform the final checks. There are no write, reset, IRQ-routing, bus-mastering or raw-register commands.

Records contain version/size, stable store ID, parent, category, independent detection flag/status, driver/name/message, transport, PCI IDs/BDF/BAR, controller/port/slot, USB class/active configuration/selected configuration/interface counts, HID interface/alternate/subclass/protocol/endpoint/DCI/MPS/USB bInterval/role, xHCI ports/slots/version/USBSTS, category-specific scalar and numeric failure code. Driver enumeration filters the same records; it does not maintain another status database. Generations let the app retry a device snapshot if it changes during copying.

## Driver integrations

- CPU: real CPUID brand and successful x86-64 startup. Memory: available RAM bytes from the validated firmware memory map, including RAM beyond the PMM allocation window.
- ACPI/HPET: actual table/clock initialization outcome. APIC: success only after routing/timer setup; fatal setup failures are recorded.
- PCI: existing full scan, BDF/IDs/class. Structured collection continues when the older PCI text report fills.
- Graphics: usable boot framebuffer dimensions and required-system status. This does not claim full runtime GPU health.
- AHCI: detected controller/BDF/IDs/BAR and actual initialization result. Registered block devices and mounted PSF state are reported separately.
- VirtIO Block/Net/Input: actual preparation/initialization/activation results with PCI metadata. Network/input registries publish logical readiness and removal.
- HDA: existing transport snapshots provide PCI controller, responsive-codec count, transport failure stage and output readiness. An exhausted boot probe is a timeout, not perpetual initialization. Audio errors do not alone trigger serious-startup autostart.
- xHCI: each existing controller publishes independent metadata/result. USB configuration and each HID interface publish from existing enumeration/activation; normal completion logs cannot downgrade readiness. HID metadata is published before endpoint setup, configuration failures remain failures, and active configuration is published only after SET_CONFIGURATION succeeds. Runtime endpoint failures/controller retirement/removal update diagnostic state.
- OHCI: actual controller initialization and runtime controller failure. Existing OHCI limitations remain.
- PS/2: independent i8042, keyboard, auxiliary-port and mouse records. An auxiliary port becomes confirmed only after an actual device response; failed probes never publish OK.
- Unsupported NVMe, UHCI/EHCI and unclaimed PCI network controllers are identified using the existing inventory and reported as unbound/missing native drivers.

Remaining coverage limits: no ACPI touchpad discovery; no HID-over-I2C; no full runtime GPU/storage health model or per-stage AHCI/PS/2 error catalog; OHCI device/interface details remain less extensive than xHCI; unknown PCI functions remain inventory records when no driver publishes a binding. Existing USB hub, generic NKRO/consumer delivery and alternate-configuration limitations are unchanged. ASUS GA401IV and Acer Nitro 5 have not been physically tested here.

A future HID-over-I2C driver belongs behind ACPI resource discovery and an I2C controller/IRQ transport. It should parse reports in the kernel and deliver through `InputDevice`, `input_register_device`, `input_dispatch_events`/report submission and the common pointer abstraction. It should publish a `DIAG_TOUCHPAD` binding with `DIAG_TRANSPORT_I2C` and an actual ACPI parent. No Ring 3 hardware API is needed.

## Application and integration

Four native tabs provide **Stan systemu**, **Urządzenia**, **Sterowniki**, **Log uruchamiania**. The device view uses an indented virtual table; driver and log views use the same existing virtual-table component. The overview displays warning/error counts with the themed informational/error banner. Native controls provide resizing, focus, minimize/restore, close, taskbar/Alt+Tab integration, live themes and Polish Unicode text.

Log filters: Wszystko, Błędy, Ostrzeżenia, USB, PCI, Input, Dźwięk, Dyski, Sieć. Selecting a log/device/driver exposes its full message in the standard read-only multiline control, where selection and Ctrl+C are available. **Kopiuj raport** exports the complete UTF-8 report through the existing clipboard API.

The protected desktop launcher and Start menu entry are both **Diagnostyka systemu**. The package is `/programy/diagnostyka.cebula/diagnostyka.bur`, with the existing manifest conventions, trust level 3 and only GUI/file read/file write rights. A small native themed monitor/pulse icon uses existing window-manager icon primitives. The bootstrap directory list includes the package directory.

## Startup and reports

Preferences live in the existing PSF user tree at `/uzytkownicy/DIAG.CFG`:

```text
autostart=1
problems=1
```

Both default to enabled. Parsing is bounded to 128 bytes, accepts only exact known keys/0-or-1 values, and ignores malformed/unknown values. The app checks write results and file size. No new settings service is introduced, and the global user path survives A/B application-slot changes. Live RAM-only sessions naturally lose files on reboot; installed BSP2 is required for durable settings. The application explicitly warns when preferences or reports are saved to RAM.

After the existing window-manager desktop-ready notification, normal startup launches the app after one second. Failure-only startup waits 15 seconds for deferred USB initialization. Serious problems are no usable keyboard/pointer, failed required filesystem/graphics/AHCI initialization, or all detected native USB hosts failing. Missing networking, unsupported optional devices, minor warnings and HDA failure alone do not force startup. Installer mode retains diagnostics but suppresses automatic app launch.

**Zapisz raport** writes `/logi/DIAG.TXT` through ordinary Ring 3 file calls, verifies the final size and reports failures visibly. The UTF-8 plain-text report includes OS version, CPU/RAM, overall/input summary, all inventory/binding records, PCI/USB/HID metadata, audio/storage/network states, counts/codes and retained diagnostic messages. Parent IDs allow machine reconstruction of the hierarchy.

The kernel independently saves `/logi/BOOTLOG.TXT` after PSF/services are ready, then bounded settled snapshots approximately 5 and 30 seconds after desktop readiness. The report buffer is a bounded temporary heap allocation after heap/filesystem initialization; the early store requires no heap. Allocation/filesystem failures leave diagnostics in memory and preserve serial output. No diagnostic filesystem writes occur before mounting.

## Physical testing

1. Build/boot the resulting hybrid ISO using the normal UEFI path. Prefer a separate test installation when testing durable preferences. Preserve any existing disk before installation; a Live session uses RAM files.
2. Wait for the desktop and the diagnostic app. Check the desktop icon and Start entry, then resize/minimize/restore the app, switch tabs and change the system theme.
3. On GA401IV, find vendor `1022`, device `1639` under PCI/xHCI. Check every controller's index/BDF/BAR, ports, slots, version, result and USBSTS. Additional NVIDIA/other controllers should have independent entries.
4. Find the built-in keyboard by VID `0B05`, PID `1866` if that is the unit's actual device. Check configuration/interface counts and every HID child, especially interface number, protocol, endpoint/DCI and ready/unsupported state. Do not assume interface zero.
5. Try the built-in keyboard in Notatnik and an external USB keyboard/mouse on ports attached to each controller. Move/click the mouse. Confirm the overview stays healthy with PS/2 unavailable. Touchpad detection/HID-over-I2C can remain unavailable independently.
6. Save/copy a report. Collect `/logi/DIAG.TXT`, `/logi/BOOTLOG.TXT` and serial logs. If input is completely absent, wait at least 40 seconds after desktop readiness for the settled automatic log; serial is available throughout.
7. On an installed system, disable both startup checkboxes, reboot and check that the app remains closed but launches manually. Reenable normal startup and reboot again. To test failure-only startup, disable normal startup, leave problem startup enabled and remove all usable input sources in a controlled test machine.

Serial landmarks: `[xHCI controller] ... result=ready/initialization failed`, `[xHCI timeout]`, `[USB root port]`, `[USB device] ... VID/PID/configuration/interfaces/HID interfaces`, `[USB interface]`, `[USB HID descriptor]`, `[USB HID] ... endpoint configured/interrupt IN armed/interrupt completion/keyboard report decoded/pointer report decoded`, independent `[PS/2]` messages, `[DIAG] Boot report saved: /logi/BOOTLOG.TXT`, startup-preference lines and Ring 3 app/first-frame messages. Only the existing bounded first-report diagnostics are printed; the app does not log every keystroke.
