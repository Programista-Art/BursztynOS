# Bootstrap portu musl — 2026-11-13

## Stan

Repozytorium ma teraz powtarzalny bootstrap sysrootu musl 1.2.5:

- źródło jest pobierane do ignorowanego `.musl-build/`,
- archiwum jest sprawdzane sumą SHA-256,
- wrappery x86-64 musl oraz pomocnicze procedury asemblerowe używają
  `int 0x80`, czyli bramki POSIX BursztynOS,
- sysroot zawiera `crt1.o`, `libc.a`, nagłówki musl i
  `bursztyn/syscall.h`,
- `test-musl-host` buduje statyczny `hello`, sprawdza ET_EXEC, brak PT_INTERP
  i obecność instrukcji `int 0x80`.

Uruchomienie:

```text
make test-musl-host
```

## Świadome ograniczenia

To jest bootstrap libc, nie pełny port produkcyjny. Nadal brakuje:

- uruchomienia `hello` z musl w natywnym QEMU Windows,
- dynamicznego loadera ELF64 (`ET_DYN`, `ld.so`, `libc.so`),
- pełnego modelu wątków/futexów wymaganego przez `pthread`,
- weryfikacji `ls` i `cat` zbudowanych przeciwko sysrootowi.

Nie należy oznaczać etapu 2 jako ukończonego przed przejściem bramki QEMU.
