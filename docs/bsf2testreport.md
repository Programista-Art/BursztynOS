## 6. Performance (host, `-O2`, `narzedzia/profile_bsf2.cpp`, DejaVu Sans 16 px)

| Paragraph | Bytes | Glyphs | UAX #9 | Layout | Wrapped (400 px) | `caret_x` | `move_visual` |
|---|---|---|---|---|---|---|---|
| Latin | 1,800 | 1,800 | 108 µs | 2.68 ms | 2.89 ms (40 lines) | 41 ns | 72 ns |
| Arabic | 2,120 | 1,160 | 63 µs | 2.06 ms | 2.12 ms (20 lines) | 39 ns | 66 ns |
| Hebrew + digits + Latin | 1,160 | 840 | 43 µs | 1.42 ms | 1.50 ms (18 lines) | 29 ns | 103 ns |

Two performance defects were found and fixed during the session:
`caret_x` rescanned graphemes from byte 0 (40–76 µs → 30–40 ns), and
`move_visual` was O(k²) per key (now O(log k) via a caret table). Layout build
time is dominated by GSUB/GPOS coverage probing (gprof); per-lookup coverage
digests are the identified next optimization. UI layouts are cached (4 per
process), so repeated paints do not reshape.

Kernel image: end 0xE287F0 before → 0xEA57F0 after (+500 KiB including the
61,730-byte Unicode blob and the engine in 8 embedded apps); **362 KiB**
below the 15 MiB guard.

## 7. Native Bursztyn OS verification (QEMU, real kernel and Ring 3 apps)

Harness: `python3 narzedzia/bsf2_native_qemu.py` (boots the production ISO;
for forced modes, a disposable copy whose only change is `grub.cfg`).
Each run: boot → native desktop → close the System Diagnostics autostart
window → Settings → Fonts (Hebrew/Arabic preview) → read BSF counters from
the Settings process (read-only QMP observer) → Notepad (type) → Shell
(`pwd`) → serial log free of kernel/user faults.

Final binaries (app `.bin` files byte-identical between the last two ISO
builds; ISO hashes differ only by image timestamps):

|---|---|---|---|
| UEFI, virtio-vga, production ISO | 1280×720 | **2 of 4 runs pass**; 2 runs stopped by `[VIRTIO-GPU] BLAD KRYTYCZNY: Timeout polecenia kontrolnego` (`TRANSFER_TO_HOST_2D`, no device response within the guest's 500 ms deadline). In one of those, every BSF check had already passed (failure during the Notepad stage); the other run's stage was not retained. | 14.3 s |

BSF counters read from the Settings process were identical in every passing
run: Unicode blob received from the kernel; 22 layouts built (12 cache
hits), 36 shaped runs, 262 glyphs, GSUB applied in 36 runs, GPOS in 36,
**0 layout failures, 0 budget failures**; the "tables unavailable" message
never appeared; no `[PF]`, `[GP]`, `[KERNEL-PANIC]` or `[USER FAULT]`.
Screenshots `settings-fonts-bidi.png` show the Hebrew paragraph resolved RTL
with the number and mirrored parentheses placed correctly, Arabic joined with
contextual forms and the lam-alef ligature, and composed `é ä`.

**The virtio-gpu timeout predates BSF 2.0** — the same message is recorded
in `docs/start-power-png-2026-10-31/installed-gpu-timeout.txt` and
`docs/settings-start-polish-2026-10-31/qemu-parallel-display-failure.log`
(both 2026-10-31, before this work). It occurs in the kernel's virtio-gpu
control path while QEMU (TCG, single thread) also serves QMP polling and
screendumps; BSF 2.0 does not touch that path, and BIOS/std-VGA runs never
showed it. Its frequency with and without BSF 2.0 was not A/B-measured in
this session, so the 1280×720 UEFI result is recorded as intermittent, not
as a pass.

Not verified: installed-disk boot (not run), Windows QEMU, physical
hardware, native RTL **typing** in Notepad (QMP `send-key` cannot produce
non-ASCII; RTL editing logic is covered by host tests on the production
Notepad code).

## 8. Changes to existing tests

`testy/test_bsf_ui.cpp`: the assertion that drawing `e◌́x` produces three
bitmaps encoded per-code-point rendering. BSF 2.0 composes `e+U+0301` to the
font's precomposed `é` (the HarfBuzz-equivalent result), so two bitmaps are
drawn; the test now asserts that, and that the drawn x of `x` equals the
caret from the same layout. No other existing assertion was changed and no
security check was weakened.
